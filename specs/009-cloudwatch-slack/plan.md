# Implementation Plan: Optional CloudWatch Slack routing

## Summary and approved scope
Extend terraform-aws-grafanav12 with an opt-in grouped cloudwatch_slack input. The user explicitly requested implementation and selected the shared AWS wrapper extension; proceed through the full Spec Kit chain in this downstream repository. No core/on-premise or other repository module changes are required. Disabled defaults preserve existing consumers, source topic ownership and provider ~>5.0 / Terraform ~>1.3 constraints.

## Technical context and wrapper choice
Add a narrow root input with enabled=false, optional primary topic_arn, additional_topic_arns=set(string), contact_point=Slack, optional function_name and log_retention_days=7. Reuse the named existing Slack incoming webhook; reject enabled configuration without that webhook. Isolate AWS adapter logic in modules/cloudwatch-slack, called only when enabled. Wrap terraform-aws-modules/notify-slack/aws 6.7.0 (closest maintained provider collection capability) and DasMeta SQS module 1.5.1; explicitly use supported Python 3.12 runtime, source-scoped SNS invocation, log retention and asynchronous dead-letter queue. Do not recreate the Lambda implementation or expose its full upstream surface. Module owned function names stay within the upstream IAM role length limit.

## Multi-region architecture
The maintained notification module always owns one local SNS subscription even when create_sns_topic=false, so require one primary source ARN in the default provider region. Additional same-account standard topic ARNs in default-enabled commercial regions use AWS::SNS::Subscription in one aws_cloudformation_stack; Region is derived from each topic ARN. AWS's official resource-handler source confirms Region selects the client for both create and delete. Add unique SHA256-derived Lambda permission Sids per additional ARN and an explicit stack dependency on every permission. Use stable hash-derived CF logical IDs. Do not manage the primary subscription in CloudFormation, infer a primary from sorted input, adopt old subscribers, create SNS topics, or edit topic policies. Restrict additional regions initially using aws_regions opt-in-not-required data; reject FIFO/cross-account/cross-partition/malformed/primary-duplicate inputs. Avoid provider aliases/bump, imperative local-exec or custom AWS SDK subscription code.
